# Shared information changes use proposals and direct changes

Tsugi no longer resolves competing shared information with trust scores. Shared information changes are made either through change proposals, which become active after two target-scope approvals or are rejected after two target-scope rejections, or through direct changes, which become active immediately while still following creator scope. Accepted proposals and direct changes are recorded in a change log, while the current active shared information is maintained as a read model for student-facing plans or views, such as daily plans and multi-day plans, including when inspected through reference scopes. This keeps routine school-life relays fast, avoids difficult automatic conflict detection, and preserves student-only review for ordinary proposed changes without treating shared information as official school information.

Student Display Names attached to Direct Changes are exposed only in Edit History after the requesting Student is confirmed inside the Target Scope. Ordinary layer-state and plan read models omit attribution. Reference Scope inspection does not reveal participant names. Future Change Proposal history may expose proposer, approving Student, and rejecting Student Display Names under the same Target Scope rule.
